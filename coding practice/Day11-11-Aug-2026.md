Interview question: 
VM vs Containerization?

VM - 
Every operating system creates its own kernel.
All OS’s installed can have the different kernel than the main kernel 
(VM is bulky in size and has own dedicated OS.)

Containerization - 
Same kernel
 All microservices use the kernal of the container
(Containers are small light weight in size. and use shared OS.)

Strong man can survive anywhere. more than weak.
Linux kernel can survive anywhere. more than windows.

Hence, 
Linux container can be hosted on Windows kernel (host OS) --WSL/2
Windows container cannot be hosted on Linux kernel (Host OS)

Inference conclusion : containers are light-weight fast because they are using host kernel

IMP: 
VM keeps running even if it is no longer in use
Containers are affimeral which means they get destroyed (killed) automatically when not in use 

TRIVIA:
Workaround to run Windows container on Linux host- have to use a hypervisor (Windows VM) in middle.

------------------------

COPY vs RUN vs CMD vs EntryPoint

COPY - copy required files into image (at work directory) during build time
copy is not mandatory for every docker file - - You have application ready on your local and you want to run it on Docker, hen copy is required so that you can copy the project files.

RUN -  mandatory commands at build time
CMD - default runtime commands - - ( optional Can be overridden ) - - Fn providing default args
EntryPoint - main runtime executable - - (cannot be easily overridden) - - Fn providing custom args
